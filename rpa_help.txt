
interval 을 weekly로 선택시 방법

1) 기본 요일 토큰(가장 안전)
mon, tue, wed, thu, fri, sat, sun (월~일)
숫자도 가능: 0-6 (APScheduler에서 첫 요일은 월요일 → 0=mon … 6=sun)
권장: 사람이 보기 쉬운 mon,tue... 형태를 쓰세요.

2) 입력 형식(자주 쓰는 패턴)
A. 단일 요일
mon → 매주 월요일
B. 여러 요일(콤마로 나열)
mon,wed,fri → 월/수/금
✅ 중요: 가능하면 공백 없이 mon,wed처럼 쓰세요. (mon, wed는 환경/버전에 따라 오동작할 수 있어요)
C. 범위(대시)
mon-fri → 월~금(평일)
sat-sun → 토~일(주말)

3) UI에서 “시간”은 어디서 고르나?
weekly는 요일(Weekly DOW) + 시간(Daily Time) 을 같이 씁니다.
예)
Trigger Type: weekly
Weekly DOW: mon,wed,fri
Daily Time: 09:10
→ 매주 월/수/금 09:10 실행

4) 추천 예시 모음
매주 월요일 09:00 → mon
평일(월~금) 08:30 → mon-fri
주말(토/일) 10:00 → sat,sun
화/목 14:20 → tue,thu

5) 자주 하는 실수(피하면 좋아요)
월,수,금 같은 한글 요일 → ❌ (mon,wed,fri로)
Mon,Wed 같이 대문자/혼합 + 공백 → 되기도 하지만, 소문자 + 공백 없음을 권장
1-5 같은 숫자 범위 → APScheduler는 0-6 체계라 헷갈릴 수 있음(권장: mon-fri)


#/////////////////////////////////////////////////////////////
flow Runner - YAML로 정의한 여러 작업(step)을 순차 실행하고, 실행 결과를 로그/출력 파일로 남기며, step의 성공/실패에 따라 분기(on) 할 수 있는 경량 실행기입니다.
Quick Start)
설치

Python 3.x
필수 패키지: pyyaml (코드에서 yaml 사용) 
pip install pyyaml
실행
python flow_runner.py flows/flow_A1.yaml

설정 검증만(실행 안 함)
python flow_runner.py flows/flow_A1.yaml --dry-run

--dry-run은 설정 검증 후 steps 목록만 출력하고 종료합니다. 
flow_runner

2) CLI 사용법
python flow_runner.py <flow_yaml> [--name NAME] [--start STEP_ID] [--log-dir DIR] [--timeout SEC] [--dry-run]

옵션 목록(코드 기준): 
flow_yaml : 실행할 YAML 파일 경로(필수)
--name : 로그에 표시할 Flow 이름(미지정 시 YAML name 또는 파일명 stem 사용) 
--start : 특정 step id부터 시작(기본은 첫 step) 
--log-dir : 로그 디렉터리 강제 지정 
--timeout : 전역 timeout 강제 지정(초). globals.timeout_sec보다 우선 
--dry-run : 실행 없이 검증 + step 목록 출력 


3) YAML 포맷
최상위 구조
name (선택): Flow 이름
globals (선택): 공통 설정
steps (필수): step 리스트
steps는 비어있지 않은 리스트여야 합니다(검증 로직). 

globals 예시
globals에서 주로 쓰는 키:
python : 실행에 사용할 Python 경로(미지정 시 sys.executable) 
workdir : 모든 step 실행 시 기본 작업 디렉터리 
timeout_sec : 기본 timeout(초) 

step 정의(필수/권장)
각 step은 dict이며, 최소 아래를 만족해야 합니다. 
id : 고유 식별자(중복 불가) 
cmd : 반드시 리스트(list) 형태로 작성 
(선택) name : 로그용 표시 이름
(선택) timeout_sec : 해당 step에만 timeout 적용(전역보다 우선) 
(선택) on : 성공/실패에 따른 다음 step 분기(아래 참고)

4) 분기 규칙(on)
지원 형태
문자열: 무조건 다음 step
on: a2
on이 문자열이면 rc와 무관하게 그 step으로 이동합니다. 
dict: 성공/실패/항상/기타(next)
on:
  success: a2
  fail: a3
  always: a4
  next: a5

선택 로직: rc==0이면 success, rc!=0이면 fail, 그 외 always, 마지막으로 next 순서입니다. 

추가 지원(레거시/편의)
step 최상위에 아래 키를 둬도 on dict로 흡수합니다:
next는 success로 간주(가장 안전한 처리) 
fail, success, always도 동일하게 병합 

5) 토큰 치환(템플릿)
cmd 내부 문자열에 다음 토큰을 쓰면 실행 전에 치환됩니다. 
{python} : globals.python 또는 현재 파이썬 실행파일 
{flow_dir} : flow yaml이 있는 폴더 
{log_dir} : 결정된 로그 폴더 
{stamp} : 실행 타임스탬프(YYYYmmdd_HHMMSS) 

6) 로그/출력 파일
로그 폴더 결정 우선순위
--log-dir > globals.log_dir > <yaml_dir>/logs 
생성 파일
메인 로그: <log_dir>/<flow_name>_<stamp>.log 
step 출력(out): <log_dir>/<flow_name>_<stamp>_<step_id>.out.txt 
표준출력/표준에러는 step out 파일에 합쳐서 저장됩니다(stderr=STDOUT). 

각 step 종료 후 out 파일의 마지막 일부(tail) 가 메인 로그에 함께 찍힙니다. 

7) 종료 코드(Exit Code)
0 : 모든 실행 step rc가 0 (OK)
1 : 실행은 완료했지만 실패(rc!=0) step이 존재 
2 : 설정/검증 오류(파일 없음, YAML 검증 실패, unknown step, loop 감지 등)
step 실행 중 예외 시 반환 코드(내부 규칙):
timeout 발생: rc=124 
실행 파일 미존재: rc=127 

8) 예시 YAML 템플릿
name: FlowA
globals:
  python: C:/Users/you/AppData/Local/Programs/Python/Python313/python.exe
  workdir: C:/access/rpa
  timeout_sec: 600
  log_dir: C:/access/rpa/flows/logs

steps:
  - id: a1
    name: Excel -> LLM 변환
    cmd: ["{python}", "{flow_dir}/../convert_excel2llm2.py", "{flow_dir}/../summary/매출실적.xlsx", "--formats", "txt", "--data-only", "--outdir", "{flow_dir}/../summary"]
    on:
      success: a2
      fail: a_fail

  - id: a2
    name: 다음 작업
    cmd: ["{python}", "{flow_dir}/../some_task.py"]
    on: a_done

  - id: a_fail
    name: 실패 처리
    cmd: ["{python}", "{flow_dir}/../notify_fail.py"]

  - id: a_done
    name: 종료
    cmd: ["{python}", "-c", "print('DONE')"]

주의: cmd는 반드시 리스트로 작성해야 합니다. 

9) 자주 발생하는 오류 체크리스트
steps가 비어있거나 리스트가 아닙니다 → steps: 아래가 리스트인지 확인 
cmd는 리스트 형태여야 합니다 → "python script.py ..." 같은 문자열 1개로 쓰지 말고 ["python","script.py",...] 형태로 작성 
다음 step id 오타 → on이 참조한 step이 steps에 없으면 검증 실패 
무한 루프 → 동일 step 재방문 시 loop 감지 후 종료 

10) Windows 인코딩(Unicode) 관련
Windows 콘솔(cp949)에서 print()가 죽지 않도록 stdout/stderr를 UTF-8로 안전 설정하며, 출력이 깨질 수 있는 경우에도 실행이 중단되지 않게 방어 로직이 들어있습니다.
또한 tail 출력은 utf-8 → cp949/euc-kr 등 순서로 decode를 시도해 가능한 내용을 복원합니다. 

11) 운영 권장사항(사내 기준)
비밀정보(API Key, 비밀번호 등) 를 YAML에 직접 적지 말고, 환경변수/별도 시크릿 저장소를 사용하세요.
step별로 timeout_sec를 지정해 “걸리는 작업”과 “빨리 실패해야 하는 작업”을 분리하세요. 
배포 전에는 반드시 --dry-run으로 검증 후 운영 반영하세요
